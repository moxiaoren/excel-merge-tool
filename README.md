# Excel 表格合并工具（行匹配版）

纯前端 Excel 表格合并工具，支持多文件上传（xlsx/xls/csv）、人员过滤、列映射（目标列 + 多源列）、预设映射、按行合并导出。

**双引擎架构（v3.1.0）**：默认纯静态、数据本地处理；可选部署一个后端（`server.js`）用于承载超大文件，避免浏览器内存崩溃。

---

## 数据安全声明（请务必阅读）

| 场景 | 数据去向 | 安全级别 |
|------|---------|---------|
| 文件 **≤ 50MB** | **浏览器本地处理**，不上传任何数据 | 高（数据不离开本机/浏览器） |
| 文件 **> 50MB** 且 **未部署后端** | 浏览器本地处理，但**可能内存不足而崩溃**（会显示预警） | 高（同样不上传，但能力受限） |
| 文件 **> 50MB** 且 **已启用后端** | **文件会通过 HTTP 上传到后端服务器**解析合并 | 中（依赖你的服务器网络与安全配置） |

> **明确说明（避免误解）：**
> - 只有当「文件超过 50MB **且** 已启用后端」时，文件内容才会上传给后端服务器处理；其余情况全部在浏览器本地完成。
> - 后端传输**未经加密时可能被局域网/网络截获**，服务器也会**短暂持有**文件内容用于解析合并，处理完成后需通过清理释放。
> - 本项目**不提供文件加密存储**。若数据敏感，建议：小文件一律本地处理（不触网）；大文件确保后端走 HTTPS，或评估公司内网环境后再启用后端。
> - 阈值说明：**≤50MB 本地 / >50MB 且有后端时才上传**。以上可在 `engine.js` 的 `REMOTE_MIN_MB` 变量调整。

## 功能
- 多文件上传：xlsx / xls / csv
- 人员过滤：名单管理，按合并字段过滤
- 列映射：目标列 + 多源列，支持点选、拖拽、下拉补挂
- 预设映射：字段模板 / 映射方案两套预设，可保存与管理
- 映射预览：合并前可视化检查匹配与留空
- 按行合并导出：日期格式化、extractChineseName、备注截断等
- 本地持久化：人员名单、当前映射、自定义预设存于 localStorage
- 源列名池：固定悬浮 + 可收纳（窄屏友好）

## 快速开始（纯静态，无需后端）

直接打开 `index.html` 即可（或访问 GitHub Pages 在线版）。支持现代浏览器（含 Web Worker）。

```bash
# 或用本地 HTTP 服务器启动（推荐，可启用 Web Worker 后台解析）
python -m http.server 8000
# 浏览器访问 http://localhost:8000/
```

> 纯静态模式下，单文件建议控制在 **≈80MB 以内**；超出会显示红色预警（提示可能内存崩溃、建议拆分或多个小文件）。

## 部署方式二：启用后端处理超大文件（可选）

当文件超过 50MB，浏览器本地解析内存峰值可达 3-4GB，极易崩溃。若你的服务器可运行 Node.js，部署 `server.js` 即可让大文件交由服务器处理，浏览器零压力。

### 1. 部署并启动后端

```bash
# 在你服务器的任意目录放置本项目（至少需要 index.html、core.js、server.js、vendor/）
node server.js 8787
# 服务器内存充足时，建议加大 Node 堆上限：
node --max-old-space-size=8192 server.js 8787
```

默认监听 `8787` 端口（可用第一个参数改端口）。

### 2. 启用安全校验（可选，推荐生产环境）

默认后端是**无鉴权**的，任何人能访问该地址上传文件。若要暴露到公网/内网供同事使用，建议：

**方式 A —— 简单校验 token**：在 `server.js` 的 `route()` 中每个 `/api/*` 入口前校验请求头。例如仅允许带 `X-Token` 且值匹配的请求。

**方式 B —— 网络层限制**：只让公司内网/特定 IP 访问，或用反向代理加 HTTPS（如 Nginx 配 ssl）。

### 3. 前端启用后端

在 `index.html` 中配置后端地址（默认为空，表示纯静态）：

```html
<!-- 示例：后端地址填入你部署 server.js 的主机端口，留空则纯静态本地处理 -->
<script>window.BACKEND_URL = 'http://你的服务器IP:8787';</script>
```

配置后，前端启动时会自动探测 `/api/health`；探测成功后，**超过 50MB 的 xlsx 自动走后端**，≤50MB 仍本地处理（隐私折中）。同事无需任何安装，打开页面即自动生效。

## 后端接口（server.js）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/health` | GET | 前端探测后端是否可用 |
| `/api/parse` | POST | 上传文件二进制（`?name=文件名.xlsx`），返回 `{sheetNames,totalRows,sheetHeaders,sheetRows,wbId}`，workbook 留存服务器 |
| `/api/merge` | POST | `{sources:[{wbId,sheet,headers}],mapping,staffEnable,staffList}`，返回 `{data:[...]}` |
| `/api/cleanup` | POST | `{wbId}` 释放服务器内存 |

## 架构（v3.1.0）

- `core.js`：纯业务逻辑（解析/表头/合并/格式化/过滤/备注处理），不依赖 DOM，可单元测试
- `engine.js`：执行引擎，按序尝试「后端 → Web Worker → 主线程降级」，`processRemarkColumn` 统一在引擎层处理保证语义一致
- `worker.js`：Web Worker 消息处理，承担本地大文件解析与批量合并
- `server.js`：可选后端（纯 Node 零依赖），复用 `core.js`，承载 >50MB 文件
- `app.js`：UI 层与全局状态（单一 `state` 对象），只持有轻量元数据
- 单元测试：`node --test test/`
